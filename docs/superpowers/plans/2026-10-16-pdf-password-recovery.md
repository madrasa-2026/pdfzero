# PDF Password & PIN Recovery Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dedicated, 100% client-side PDF Password & PIN Recovery tool (`/tools/recover-pdf-password`) on AirPDF that uses background Web Workers to rapidly scan 4-digit numeric PINs, common patterns, and user clue permutations without freezing the UI or sending any bytes to external servers.

**Architecture:** A pure client-side Astro Island (`RecoverPdfPasswordIsland.astro`) orchestrating a dedicated Web Worker (`pdf-recovery.worker.js`). Candidate passwords are generated by `src/lib/pdf/recover.ts` and evaluated against the PDF cryptographic header in parallel batches. Upon match, the engine displays the password and immediately offers a 1-click decrypted PDF download via `unlockPdf()`.

**Tech Stack:** Astro, TypeScript, Tailwind CSS, `pdfjs-dist`, `pdf-lib-with-encrypt`, Web Workers, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-recover-pdf-password-design.md`

## Global Constraints

- **Execution Model:** 100% in-browser client-side execution using Web Workers. Zero bytes or candidate passwords sent to any server.
- **Zero UI Freezing:** All password candidate evaluations must execute strictly off the main thread in a Web Worker, throttled to 10-15 FPS progress updates for smooth 60fps UI rendering.
- **No File Size Limit:** Leverages client-side ArrayBuffer streaming without artificial caps.
- **One-Click Permanent Decryption:** On password discovery, provide 1-click "Download Clean Unlocked PDF" via `unlockPdf()` in addition to displaying the plaintext password and copy button.
- **Honest Cryptographic Disclosure:** Clear messaging that AES-256 cannot be brute-forced for arbitrary long random passwords, setting realistic expectations while maximizing success for common PINs and personal memory clues.

## Review Focus

1. **Worker Lifecycle Stability:** Terminating, pausing, or switching files must gracefully abort worker processing without orphan loops or memory leaks.
2. **Speedometer & Battery Throttling:** Progress events must be batched (e.g. every 50–100 attempts or every 100ms) so the main thread is never flooded with postMessage overhead.
3. **Decryption on Match:** Verifying that a candidate password unlocks the PDF must be 100% accurate without false positives or false negatives across AES-128, AES-256, and RC4 PDFs.
4. **Permutation Deduplication:** Clue generator must strip duplicates, whitespace, and empty strings to avoid wasting worker CPU cycles.
5. **Mobile Responsiveness:** The live scanning dashboard and controls must render cleanly on narrow mobile viewports (< 375px) as well as desktop displays.

### Task 2: Background Web Worker & Client Controller

**Files:**
- Create: `public/workers/pdf-recovery.worker.js`
- Create: `src/lib/pdf/recoveryWorkerClient.ts`
- Test: `tests/pdf/recoveryWorker.test.ts`

**Interfaces:**
```typescript
export interface RecoveryProgress {
  stageId: string;
  stageLabel: string;
  tested: number;
  total: number;
  currentCandidate: string;
  speed: number; // tests/sec
  percent: number;
}

export interface WorkerCallbacks {
  onProgress?: (progress: RecoveryProgress) => void;
  onFound?: (password: string) => void;
  onExhausted?: (stageId: string) => void;
  onError?: (err: string) => void;
}

export class RecoveryWorkerClient {
  constructor(workerUrl?: string);
  async init(pdfBytes: ArrayBuffer): Promise<{ isEncrypted: boolean }>;
  start(batches: { stageId: string; label: string; candidates: string[] }[], callbacks: WorkerCallbacks): void;
  pause(): void;
  resume(): void;
  stop(): void;
  terminate(): void;
}
```
